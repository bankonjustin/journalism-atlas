# Phase 3a — header theme switch (white default, no visible change)

*2026-10-06. Files: `assets/css/header.css`, `assets/js/header.js`, plus a comment-only edit in `research/nodes-and-networks.html`.*

## What was built
- **Switch:** `data-header-theme="white|black"`, set by `header.js` on `<html>` and on `<nav id="siteTopNav">`. A page may request a theme with `<html data-header-theme="…">`; anything else falls back to `white`. **White is the default and the only live option.**
- **Variables on `:root`, not on the nav.** Custom properties only inherit downward, so anything docked outside the nav can only read the theme from `:root`. `--header-bg` is the single shared variable for docked elements. Others: `--header-border`, `--header-border-scrolled`, `--header-fg`, `--header-fg-hover`, `--header-logo-fg`, `--header-badge-fg/-border`, `--header-menu-bg/-border/-fg/-hover-bg`.
- **White values are exactly the old values** (same `var(--white)`, `#ddd`, `#e5e5e5`, `var(--dark-gray)`, `var(--black)` …), so nothing changes. Covered: nav bar, scroll-shrink state (border/shadow), logo link, nav links + hover, "Soon" badge, hamburger, mobile drawer (bg, header rule, links, hover, close).
- **Black theme CSS exists but is unwired.** `header.js` has a one-entry theme map; the black entry is commented out because `Atlas_logo_lockup_horizontal_wht_web.svg` is not in the repo. Requesting `black` today falls back to white. No SVG was created or recolored. Black values follow v12 (nav text step 1, border step 5, hover lime `#97d600`) and **have not been reviewed visually**; properties the white header leaves at browser defaults (search input bg/text/placeholder, drawer text color) are set only inside the black selector so white is untouched.
- **Search button and pulse dot stay lime** in both themes (not part of this pass). The search-button hover is still olive per ruling 4.
